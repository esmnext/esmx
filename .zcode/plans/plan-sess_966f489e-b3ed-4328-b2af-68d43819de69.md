## 目标

本地一条命令 `pnpm release <版本号>`，自动完成：版本 bump → 门禁检查 → 提交/tag/推送 → 触发 CI 发布（带 npm provenance 签名）。全程零交互、零 Touch ID，对 agent 触发友好。

## 整体流程

```
本地 (pnpm release 3.0.0-rc.120):
  1. 校验：参数、git 干净、版本号合法、未冲突
  2. 门禁：lint:type + test（全过才继续）
  3. build:packages
  4. dist-tag 判定：版本号含 - → tag=rc；否则 tag=latest
  5. lerna version <版本号> --no-push --exact --yes（bump + commit + tag，本地）
  6. git push origin master --follow-tags
  7. gh run list 取最新 release workflow run，回显 URL（不等待）
  8. 输出结构化结果 JSON（给 agent 解析）

CI (.github/workflows/release.yml，v* tag 触发):
  1. 门禁：lint:type + test（双保险）
  2. build:packages
  3. npm publish --workspaces --provenance --tag <rc|latest> --access public
     （npm CLI 原生 provenance，16 包，零 OTP：Automation token + OIDC）
  4. environment: release（GH 页面需人工 approve——agent 触发时由你预先放行/或配 auto-approve）
```

## 为什么这么设计（关键决策）

| 决策 | 原因 |
|---|---|
| **本地不 publish，交给 CI** | (1) provenance 必须 GHA+OIDC 签，本地发不出徽章；(2) CI 用 Automation token 绕过你账号的 security-key 2FA，不用逐包按 Touch ID |
| **用 npm publish --workspaces 而非 lerna publish** | pnpm 不支持 --provenance、lerna 8 也不透传 --provenance。只有 npm CLI 原生支持 --provenance。npm -w 递归发 workspace 包，等价 lerna from-package |
| **脚本不等 CI 完成，只回显 URL** | 你明确说"以后都是 agent 触发，人不看"，且 agent 可用 `gh run watch <id>` 自行轮询。脚本职责单一：触发 |
| **dist-tag 按版本号自动判定** | prerelease（含 `-`）发 `rc`，正式版发 `latest`。符合 semver 惯例，`npm i` 装正式版、`@rc` 装 RC |
| **本地+CI 双门禁** | 本地快反馈（发版前就拦），CI 作为最终防线（防止有人绕过脚本直接 push tag） |

## 改动清单（4 个文件）

### 1. 新建 `scripts/release.mjs`（本地发布脚本）

核心逻辑（伪代码）：
```js
// 解析参数：pnpm release <version>
// 1. 前置校验
//    - 参数存在；版本号符合 semver
//    - git 工作区干净；当前分支 master
//    - registry 上该版本未发布（防重复）
//    - 本地版本号 < 目标版本号
// 2. 门禁：exec('pnpm lint:type') + exec('pnpm test')，失败即退出
// 3. build：exec('pnpm build:packages')
// 4. 判定 dist-tag：/-/.test(version) ? 'rc' : 'latest'
// 5. bump：lerna version <version> --no-push --exact --yes --force-publish
//    （--no-push 让我们自己控制 push，便于失败回滚）
// 6. push：git push origin HEAD --follow-tags
// 7. 回显 CI URL：用 gh 取最近触发的 release run
// 8. 结构化输出（JSON 给 agent）
```

失败回滚：bump 后 push 前若门禁/build 失败 → `git reset --hard HEAD~1` + 删本地 tag；push 失败 → 同样回滚本地。

结构化输出（agent 友好）：
```json
{
  "status": "triggered",
  "version": "3.0.0-rc.120",
  "distTag": "rc",
  "tagCommit": "abc1234",
  "ciRunUrl": "https://github.com/esmnext/esmx/actions/runs/...",
  "next": "等待 CI 发布完成。轮询：gh run watch <run-id>"
}
```

### 2. 新建 `.github/workflows/release.yml`

```yaml
name: Release
on:
  push:
    tags: ['v*.*.*']        # 包含 v3.0.0-rc.120 和 v3.0.0
  workflow_dispatch:         # 备用：手动触发（带版本号）
    inputs:
      version:
        required: true

permissions:
  contents: read
  id-token: write            # ← provenance 的 OIDC 签名权限，关键

concurrency:
  group: release
  cancel-in-progress: false

jobs:
  publish:
    runs-on: ubuntu-latest
    environment: release     # ← GH environment 审批门（你可在 settings 里配 required reviewers）
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - uses: pnpm/action-setup@v2
        with: { version: 10 }
      - uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: pnpm
          registry-url: https://registry.npmjs.org
      - run: pnpm install --frozen-lockfile
      - run: pnpm build:packages
      - name: Verify pre-release tags
        run: node scripts/verify-release.mjs   # 从 git tag 读版本号，算 dist-tag
      - run: pnpm lint:type
      - run: pnpm test
      - name: Publish with provenance
        run: npm publish --workspaces --provenance --access public
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
          # dist-tag 通过 scripts/set-publish-tag.mjs 或 npm_config_tag 注入
```

dist-tag 注入：CI 里 npm 不支持直接在 `--workspaces` 下传 `--tag` 给所有包（旧 bug），所以用一个前置步骤把 tag 写进 `.npmrc`（`npm config set tag rc`，作用当前 job），或用环境变量 `npm_config_tag`。会在实现时验证哪种稳，优先环境变量。

### 3. 新建 `scripts/verify-release.mjs`（CI 端校验+算 tag）

从 `GITHUB_REF`（tag 名）解析版本号 → 判定 dist-tag → 写入 `$GITHUB_ENV`（供后续 step 用）。同时校验 registry 上该版本未发布（防重发）。

### 4. 改 `package.json` scripts

```json
"release": "node scripts/release.mjs"
```
（替换原 `pnpm run build:packages && npx lerna publish ...`，build 移入脚本内做门禁顺序控制）

## 你需要手动做的（一次性，没法脚本化）

1. **创建 npm Automation Token**：https://www.npmjs.com/settings/lzxb2015/tokens/new → Classic Token → **Automation**（绕过 2FA）。这是 CI 唯一能零交互发布的 token 类型。
2. **配 GH secret**：仓库 Settings → Secrets → Actions → New `NPM_TOKEN`。
3. **配 GH environment**（可选但推荐）：Settings → Environments → New `release` → 配 required reviewers（你自己）。配了之后 agent 触发时，CI 会停在审批步，你/我在 GH 页面 approve 后继续。

## 三个未定的实现细节（实现时验证，不阻塞方案）

1. **npm publish --workspaces --provenance 是否给 16 个包都签名**：npm 文档说 workspace 模式下每个包独立签，但版本兼容性以实测为准。若不行，退路是 `pnpm -r --filter './packages/**' exec npm publish --provenance`。
2. **dist-tag 注入方式**：优先 `npm_config_tag` 环境变量，退路写 `.npmrc`。
3. **lerna version --no-push 后的 push**：lerna 默认会自己 push，加 `--no-push` 后我们手动 `git push --follow-tags`，确保失败可控。

## 不会动的

- 各包 `package.json`（版本号由 lerna 自动 bump）
- 现有 build.yml/regression.yml（保留）
- `prepare.mjs`、husky 配置
